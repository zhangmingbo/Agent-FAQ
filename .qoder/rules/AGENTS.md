# 强制存档规则（每次会话生效）
每次完成一个用户请求（写完代码、改完文件、修完 bug）后，必须依次执行：
1. git add -A
2. git commit -m "feat: <本次改动的简短中文摘要>"
3. 如果 git status 显示无改动，跳过提交即可

# 开发流程四阶段规范（每次需求必须遵循）

## 阶段一：需求确认
用户提供需求时必须包含以下要素，缺一不可：
- 【目标】：本次变更要达成什么
- 【背景】：为什么要做这个变更
- 【约束】：限制条件、不能破坏的现有功能
- 【输出】：交付物是什么
- 【验收标准】：怎样算完成

## 阶段二：方案设计
收到需求后先输出实施方案，用户确认后才进入开发：
- 技术架构（涉及哪些模块、数据流）
- 交互时序图（Mermaid sequence diagram）
- 变更范围（具体改哪些文件、新增哪些文件）
- 测试案例（怎么验证功能正确）

## 阶段三：编码实现
用户确认方案后才开始写代码。

## 阶段四：提交存档
开发完成并测试通过后：
- git add -A
- git commit -m "feat: <本次需求的简短中文摘要>"
- 必要时打 tag（如 v2.1、v3.0 等）
- 确保版本可回退
