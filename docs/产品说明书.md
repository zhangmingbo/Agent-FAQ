## 一、产品概述

### 1.1 产品定位

智能体管理平台是一款面向企业的对话式 AI 管理系统，集 FAQ 问答、多轮任务流程、智能分析于一体。平台以"对话大脑"为核心，通过 API 对外提供智能问答能力，支持多渠道接入（微信、网页、APP 等）。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| FAQ 问答 | 基于语义相似度的知识库问答，支持分类管理、相似问扩写 |
| 多轮任务流程 | 可视化编排槽位收集、确认、接口调用、分支判断等步骤 |
| NER 实体提取 | 本地 NER 模型 + 正则后处理，支持地址/姓名/电话等 12+ 种实体 |
| 语义仲裁 | 任务流程与 FAQ 通道并行竞争，基于置信度自动路由 |
| 智能分析 | 未匹配问题挖掘、低置信度分析、表达挖掘与建议 |
| 服务监控 | 实时请求统计、意图分布、趋势图表 |
| 任务实例管理 | 跟踪每个会话中任务的执行进展 |

### 1.3 技术架构

```
┌─────────────────────────────────────────────────────┐
│  前端层（Vue3 + Element Plus + 单体 HTML 注入）       │
└──────────────────────┬──────────────────────────────┘
                       │ HTTP :3001
┌──────────────────────┴──────────────────────────────┐
│  Express.js 服务层                                    │
│  FAQ 引擎 │ 任务引擎 │ NLU │ 对话管理器              │
└──────────────────────┬──────────────────────────────┘
                       │
        ┌──────────────┼──────────────┐
        │              │              │
   ┌────┴────┐   ┌────┴────┐   ┌────┴────┐
   │  MySQL  │   │  Redis  │   │ NER 服务 │
   │ (RDS)   │   │ (会话)  │   │ (Python) │
   └─────────┘   └─────────┘   └─────────┘
```

## 二、系统部署

### 2.1 环境要求

- Node.js 18+
- MySQL 8.0+（推荐阿里云 RDS）
- Redis 6+
- Python 3.9+（NER 服务，可选）

### 2.2 启动步骤

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 填入数据库连接信息

# 3. 启动服务
node server.js
# 或生产环境
pm2 start ecosystem.config.js

# 4. 访问管理后台
# http://localhost:3001/admin/
```

### 2.3 NER 服务（可选）

```bash
cd ner-service
pip install -r requirements.txt
python app.py
# 默认端口 8766
```

### 3.8 流程设计（Rules）

流程设计页面包含 4 个页签：

#### 3.8.1 任务流程

**任务列表**
- 新建/编辑/删除任务
- 启用/禁用任务
- 支持从槽位自动生成流程步骤

**任务编辑弹窗 — 槽位定义（卡片式）**

每个槽位独立为一张卡片，支持折叠/展开，包含：

| 字段 | 说明 |
|------|------|
| 字段名（key） | 英文唯一标识，如 `phone`、`address` |
| 显示名（label） | 中文名称，如"电话"、"地址" |
| 类型 | 文本 / 正则 / 数字 / 枚举 |
| NER 类型 | 地址/姓名/公司/机构/电话/邮箱/日期/时间/政府机构/职位/场景 |
| 必填 | 是否必须收集 |
| 提问话术 | 向用户提问的文本 |
| 别名 | 用户可能的表达方式（标签式，回车添加） |
| 提取规则 | 正则表达式或枚举值（逗号分隔） |
| 校验正则 | 收集后的格式校验 |
| 校验失败话术 | 校验不通过时的重问话术 |
| 默认值 | 槽位预填值 |

**任务编辑弹窗 — 流程步骤（卡片式）**

每个步骤独立为一张卡片，支持折叠/展开：

| 步骤类型 | 说明 |
|----------|------|
| 收集（collect） | 收集指定槽位，通过 slot_key 引用槽位定义 |
| 确认（confirm） | 向用户确认已收集的信息 |
| 动作（action） | 执行动作（如 complete_message） |
| 调用接口（api） | 调用外部 API，支持字段映射、结果映射 |
| 子任务（subtask） | 调用另一个任务流程 |
| 分支（branch） | 条件判断，支持多分支 + 默认分支 |
| 回复（message） | 发送消息给用户 |

**职责分离原则**：
- 槽位定义 = 数据模型（提取规则、校验规则、话术、NER 类型）
- 流程步骤 = 流程控制器（只通过 slot_key 引用槽位，不重复配置）

## 四、核心机制

### 4.1 对话处理流程

```
用户输入
  │
  ├─ 1. 无意义检测（规则/LLM）
  │     └─ 无意义 → 提示重新输入
  │
  ├─ 2. 任务引擎检测
  │     ├─ 已有活跃任务 → 槽位提取
  │     └─ 新任务触发 → 语义仲裁
  │
  ├─ 3. FAQ 匹配
  │     └─ 语义相似度 + 正则
  │
  └─ 4. 路由仲裁
        ├─ 任务赢 → 进入/继续任务流程
        ├─ FAQ 赢 → 返回 FAQ 答案
        └─ 均未命中 → 兜底回复
```

### 4.2 槽位提取机制

1. **正则提取**：`extract_type = "regex"` 时，用正则表达式提取
2. **枚举提取**：`extract_type = "enum"` 时，匹配枚举值
3. **NER 提取**：配置 `ner_type` 时，调用 NER 模型提取
4. **标签提取**：识别"地址是X"、"电话是Y"模式
5. **防重复机制**：纯文本槽位提取后，后续文本槽位需显式标签（NER 不受此限制）

### 4.3 NER 实体提取

- **模型提取**：Python NER 服务（基于 CLUENER 模型）识别 12 种内置实体
- **正则后处理**：用户自定义正则类型，在模型结果之上补充提取
- **动态管理**：内置类型 + 自定义类型，DB 持久化，保存即生效

### 4.4 语义仲裁

任务通道和 FAQ 通道并行计算，按以下规则决出胜者：

1. **单侧过线**：任一侧置信度 ≥ 对应最低阈值且远超另一侧 → 直接赢
2. **双侧过线**：两侧都达标时，比较置信度差距是否超过 `arb_gap`
3. **强命中**：任一侧 ≥ `arb_strong_hit` → 直接赢
4. **均未命中**：触发兜底回复

## 七、常见问题

### Q1: 任务流程中 LLM 配置去哪了？

任务流程已彻底去 LLM 化，采用纯规则引擎。LLM 仅保留在 FAQ 侧的无意义检测和重排两个节点。

### Q2: 地址提取不到怎么办？

检查槽位是否配置了 NER 类型（address）。纯文本提取受防重复机制限制，NER 提取不受此限制。

### Q3: 如何新增自定义 NER 类型？

进入"流程设计 → NER 管理"页签，点击"+ 新增类型"，填写类型标识和正则表达式，保存后立即生效。

### Q4: 前端构建后功能丢失怎么办？

`public/admin/` 目录包含完整的前端构建产物 + 注入功能。从 Vue 源码构建后会覆盖注入内容。正确做法：
1. 从 git 恢复：`git checkout <commit> -- public/admin/`
2. 或确保所有注入功能已提交版本控制

### Q5: 配置修改后需要重启服务吗？

- **立即生效**：仲裁阈值、NER 类型、提示词、固定话术
- **需要重启**：任务定义（槽位/步骤结构变更）

## 十、模块功能设计

### 10.1 FAQ 问答引擎 (faq-engine.js)

**职责**：对话编排层，负责意图识别路由、无意义过滤、追问确认、兜底回复。

**核心方法**：

| 方法 | 说明 |
|------|------|
| `chat(sessionId, text)` | 主入口：处理一轮对话 |
| `detectNewTask(text)` | 检测是否触发新任务 |
| `_looksLikeSlotAnswer(text)` | 判断是否为槽位回答 |
| `route(taskResult, faqResult)` | 路由仲裁：任务 vs FAQ |
| `getSession(sessionId)` | 获取/创建会话上下文 |
| `clearSession(sessionId)` | 清除会话 |

**处理流程**：
1. 无意义检测（规则/LLM）→ 命中则提示重新输入
2. 任务引擎检测 → 已有任务则继续，新触发则仲裁
3. FAQ 匹配 → 语义相似度 + 正则
4. 路由仲裁 → 任务/FAQ/fallback

### 10.2 任务流程引擎 (taskflow/)

#### 10.2.1 引擎入口 (index.js)

**职责**：任务引擎对外契约，初始化、任务加载、NLU 接入。

**核心方法**：

| 方法 | 说明 |
|------|------|
| `initialize()` | 启动：建表 + 加载定义 + 初始化存储 |
| `matchTask(text)` | 触发词匹配 → taskDef |
| `startTask(sessionId, taskDef)` | 开始任务 → taskState |
| `processInput(sessionId, text)` | 处理一轮任务对话 → 信封 |
| `hasActiveTask(sessionId)` | 是否有进行中的任务 |
| `getActiveTask(sessionId)` | 获取任务状态 |

#### 10.2.2 自然语言理解 (nlu.js)

**职责**：意图判定、槽位提取、任务/FAQ 统一语义仲裁、路由判定。

**核心方法**：

| 方法 | 说明 |
|------|------|
| `matchTask(text)` | 意图识别：关键词 → 向量语义 |
| `arbitrateTaskFaq(text, taskResult, faqResult)` | 任务/FAQ 统一仲裁 |
| `route(text, taskState, faqResult)` | 任务进行中的路由判定 |
| `extractSlots(text, state)` | 槽位提取 |

**仲裁逻辑**：
1. 单侧过线：任一侧 ≥ 最低阈值且远超另一侧 → 直接赢
2. 双侧过线：比较差距是否超过 `arb_gap`
3. 强命中：任一侧 ≥ `arb_strong_hit` → 直接赢
4. 均未命中：触发域外快检

#### 10.2.3 对话管理器 (dialogManager.js)

**职责**：DST（对话状态追踪）+ Policy（策略），根据任务状态推进步骤流程。

**核心方法**：

| 方法 | 说明 |
|------|------|
| `processTurn(state, text)` | 处理一轮任务对话 → 信封 |
| `_isCancel(text)` | 取消意图检测 |
| `_detectCorrection(text, state)` | 槽位纠正检测 |
| `_renderConfirm(state)` | 渲染确认清单 |
| `_findNextStep(state)` | 查找下一步 |

**返回信封结构**：
```javascript
{
  reply: string,        // 回复文本
  isComplete: boolean,  // 任务是否完成
  extracted: boolean,   // 本轮有进展
  reask: boolean,       // 需要重问
  taskState: Object     // 任务状态
}
```

#### 10.2.4 槽位提取器 (extractor.js)

**职责**：从用户输入中提取槽位值。

**提取策略优先级**：
1. 关键词/标签显式提供（如"地址是XX"）
2. NER 提取（复杂槽位，不受 labelOnly 限制）
3. 正则提取（extract_type = "regex"）
4. 数字提取（extract_type = "number"）
5. 枚举匹配（extract_type = "enum"）
6. 文本兜底（受防重复机制限制）

#### 10.2.5 NER 客户端 (nerClient.js)

**职责**：调用 Python NER 服务 + 正则后处理，支持动态类型管理。

**核心方法**：

| 方法 | 说明 |
|------|------|
| `extract(text)` | 完整提取：模型 + 正则后处理 |
| `extractForSlot(text, slot)` | 按槽位定义提取 |
| `loadCustomTypes()` | 从 DB 加载自定义类型 |
| `setCustomTypes(types)` | 保存自定义类型到 DB |
| `testRegex(text)` | 正则匹配测试 |

**类型来源**：
- `source: "model"` — Python NER 模型原生识别（12 种内置）
- `source: "regex"` — 用户自定义正则后处理

#### 10.2.6 状态存储 (store.js)

**职责**：任务状态持久化适配器。

**实现**：
- `RedisStore`：生产环境，TTL 自动过期
- `MemoryStore`：开发/降级环境，进程内 Map + TTL 扫描

**接口**：
```javascript
get(key)                    // 获取状态
set(key, value, ttlMs)      // 设置状态
del(key)                    // 删除状态
keys(pattern)               // 列出匹配前缀的 key
```

#### 10.2.7 任务实例存储 (instanceStore.js)

**职责**：任务实例持久化到 MySQL，跟踪任务进展。

**核心方法**：

| 方法 | 说明 |
|------|------|
| `create(params)` | 创建任务实例 |
| `update(id, fields)` | 更新实例状态 |
| `getById(id)` | 按 ID 查询 |
| `list(filters)` | 列表查询 |
| `getStats()` | 统计卡片数据 |

### 10.3 LLM 服务层
