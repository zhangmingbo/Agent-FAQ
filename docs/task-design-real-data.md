# 客服对话分析 + 4 个任务流程设计方案

> 数据来源：`D:\沁园录音\tt.xml`（28 个真实坐席-客户微信会话，26 个有业务内容，412 条记录）
> 目的：基于真实对话抽取意图/词槽/坐席关键回复与反问，设计 4 个任务流程，
> 解决"用户问题命中任务后缺乏跟踪处理"的问题。

---

## 一、真实对话分析结论

### 1.1 意图分布（26 个业务会话，按首句+内容归类）

| 意图 | 会话数 | 代表用户原话 |
|---|---|---|
| **预约上门换芯** | 9 | "安排个上门换滤芯""能上门换滤芯吗""提醒该换滤芯啦" |
| **报修/故障排查**（红灯/复位/不出水/E9/废水多） | 8 | "我家的净水器怎么红灯啦""换滤芯后还是红色""E9代表什么""废水比好水还多" |
| **资料/教程/人工入口**（换芯视频/卸载教程/售后电话/人工） | 6 | "换滤芯视频发一下""你们人工电话多少""需要人工服务" |
| **费用咨询**（保修/换芯费/拆机费） | 4 | "保修期维修要给钱吗""换滤芯还要加60费用""你们是免费上门服务吗" |
| **预约上门服务**（移机/拆机/检测） | 1 | "想把前置过滤器移个位置"（另有多会话隐含） |
| **查单/催单/派单** | 2 | "我昨天报了个单子你查查""之前预约的麻烦让客服回电" |
| **产品/活动咨询**（回收/优惠/以旧换新） | 2 | "旧机子能回收""滤芯有没有优惠活动" |

### 1.2 词槽（坐席实际收集的信息，按频次）

电话(21) > 号码(6) > 机器型号(5) > 姓名(3) 地址(3) 购买渠道(3) 购买日期(3) > 维修/保养类型(3) > 上门时间(2) 拆机地址(1) 二次安装地址(1)

**核心发现**：坐席几乎每个服务类会话**都先要电话**（"亲~您还记得您预约安装机器时留的电话吗？我需要查询一下您的用户信息"）——**电话是查用户信息的关键，也是所有预约类任务的第一词槽**。

### 1.3 坐席关键回复句式

- **查用户后确认**："13843615426，线上，UR-A51040i-纯水机，购买时间2024-03-27，吉林省/白城市/洮南市/璀璨龙庭9号楼2单元8楼西，请问信息正确吗亲"（**用户档案确认 = 防错关键**）
- **预约成功**："给您预约好了，会有当地的售后24小时内和您联系的，您保持电话畅通亲亲"
- **费用结论**："由沁园工程师提供的滤芯，20公里之内只收滤芯费用，不收取服务费""自备滤芯上门更换20公里内60元/次""单独拆机20公里内50元"
- **派单/催单**："已派单""已反馈售后取消预约""已催促售后尽快联系上门"
- **投诉升级**："为了更好地解决您的问题，我将为您升级处理，24小时内会有专员与您联系"（会话 MEA 投诉场景）

### 1.4 反问句式（坐席引导词槽的提问）

- "亲~您还记得您预约安装机器时留的电话吗？麻烦亲提供一下这个电话"（查用户）
- "请问您的姓名，地址，电话，机器型号，购买渠道（线上/线下），购买日期这些详细信息"（建档）
- "您期望售后工程师什么时间上门服务呢亲亲"（约时间）
- "请问您尝试过拔了净水器电源插头，等待十分钟，再重新插上去也不行吗亲"（故障排查引导）
- "请问是红灯循环闪烁，还是一起闪烁亲"（故障细分）

## 二、现有任务的问题（为什么"命中后缺乏跟踪"）

对照真实对话，当前任务流程的缺陷：

1. **缺"查用户档案"步骤**：坐席第一步都是拿电话查用户（信息回显确认），现有任务直接开始收集姓名/地址，没有查档+确认，容易收集错信息。
2. **缺"预约结果跟踪"**：真实坐席预约后明确说"24小时内售后联系您"；当前任务完成后无工单跟踪概念（没有单号回显/催单能力）。
3. **故障类没有"自助排查→升级预约"分层**：真实坐席先给自助方案（拔电源重启/复位操作），解决不了才预约上门；当前无故障任务。
4. **费用咨询没有结构化**：换芯费/拆机费/保修是 FAQ 回答了，但没有"按用户情况（自备滤芯/工程师滤芯、距离）算费"的流程。
5. **触发词覆盖面窄**：真实话术"提醒该换滤芯啦""E9""废水比好水多""人工客服"都未命中任务。

## 三、4 个任务流程设计方案

> 按真实对话最高频意图设计。每个流程含：意图/触发词/词槽（含类型与校验）/机器人问句（含反问与纠错）/步骤流转/完成动作/跟踪闭环。
> 命名遵循现有 task 表结构（slots + steps DSL）。

---

### 任务 1：预约上门换芯（filter_replace）

**背景**：最高频意图（9 会话 + "提醒该换滤芯啦"场景）。用户要师傅上门换滤芯。

**词槽**（按收集顺序）：
| key | 标签 | 类型/校验 | 必填 |
|---|---|---|---|
| phone | 联系电话 | regex `1[3-9]\d{9}` | ✅ |
| machine_model | 机器型号 | text | ✅ |
| customer_name | 姓名 | text | ✅ |
| address | 服务地址 | length≥5 | ✅ |
| filter_source | 滤芯来源（沁园/自备） | enum [沁园滤芯, 自备滤芯] | ✅ |
| time_slot | 期望上门时间 | text | ✅ |

**机器人问句**：
1. `亲~您还记得预约安装机器时留的电话吗？麻烦提供一下这个电话，我需要查询您的用户信息`（收集 phone）
2. `请问您的机器型号是？（型号在机器背面或侧面的灰色铭牌上）`（machine_model）
3. `怎么称呼您呢？`（customer_name）
4. `请问您的服务地址是？`（address）
5. `这次换芯，您用的是沁园提供的滤芯，还是自己买的滤芯呢？`（filter_source，enum 反问）
6. `您期望师傅什么时间上门呢？比如上午/下午`（time_slot）
7. 确认清单 → 提交

**关键设计（跟踪闭环）**：
- 收集 phone 后**调用查档接口**（mock：`/api/mock/user/query`，body `{phone}`），**回显用户档案**："查到您的信息：{name}，{address}，{model}，请问正确吗" → 已填槽自动回填姓名/地址/型号，减少重复询问（真实坐席做法）
- 完成动作：call_api 预约接口（传 phone/model/filter_source/time_slot）→ done_message：`已为您预约上门换芯，售后会在24小时内联系您，单号 #{orderId}，请保持电话畅通`
- 分支：filter_source=自备 → 追加费用提示 `温馨提示：自备滤芯上门更换20公里内服务费60元/台`

**触发词**：换芯、换滤芯、上门换滤芯、滤芯更换、滤芯到期、提醒该换滤芯
**例句**：安排个上门换滤芯 / 能上门换滤芯吗 / 提醒该换滤芯啦 / 我今天能预约换芯服务吗

### 任务 2：故障报修与自助排查（fault_repair）

**背景**：8 个故障会话。真实坐席模式：**先自助排查（拔电源/复位/看灯）→ 解决不了才预约上门**。

**词槽**：
| key | 标签 | 类型/校验 | 必填 |
|---|---|---|---|
| fault_type | 故障类型 | enum [指示灯异常, 不出水, 废水异常, 报错代码, 漏水, 其他] | ✅ |
| machine_model | 机器型号 | text | ✅ |
| error_code | 报错代码（如 E1/E9） | text（fault_type=报错代码时） | 条件 |
| symptom | 具体现象 | text | ✅ |
| tried_steps | 已尝试操作 | enum [拔电重启, 复位, 未尝试] | ✅ |
| phone | 联系电话 | regex | ✅（升级预约时） |
| address | 服务地址 | length≥5 | ✅（升级预约时） |
| time_slot | 上门时间 | text | ✅（升级预约时） |

**机器人问句（自助排查流程）**：
1. `亲亲，您的机器出了什么问题呢？`（fault_type 枚举反问：1.指示灯异常 2.不出水 3.废水异常 4.显示报错代码 5.漏水 6.其他）
2. 分支 fault_type=报错代码 → `方便告诉我屏幕上的报错代码吗？比如 E1、E9`（error_code）
3. `请问您的机器型号是？`（machine_model）
4. **自助排查引导**（关键，减少上门）：
   - 指示灯异常/不出水 → `亲亲，您可以先把机器电源插头拔掉，等待十五分钟再重新插上试试；如果是滤芯到期，按选择键选到对应滤芯，长按复位键6秒即可复位。您试过这些操作了吗？`（tried_steps）
   - 试过仍不行 → `好的，那我们为您预约师傅上门检查` → 转入预约（收 phone/address/time_slot）
   - 未尝试 → 提示先试，返回排查
5. 确认 → 提交预约上门

**完成动作**：call_api 报修接口 → done_message：`已为您登记故障报修（单号 #{orderId}），售后工程师24小时内联系您。期间如自助排查成功可回复"取消"撤销预约`

**触发词**：红灯、不出水、故障、坏了、E9、E1、报错、复位、废水、漏水、异常、机器问题
**例句**：我家的净水器怎么红灯啦 / 换滤芯后还是红色 / E9代表什么 / 废水比好水还多 / 复位了也没好 / 我家净水器出问题了

**关键设计（跟踪闭环）**：自助排查步骤有**分支**（tried_steps=未尝试 → 引导重试，不给上门；已尝试 → 升级预约），避免"一上来就预约上门"造成无效上门；预约后单号可被"查单/催单"任务跟踪。

### 任务 3：预约查询 / 催单 / 派单状态（order_track）

**背景**：真实会话有"我昨天报了个单子你查查""之前预约的麻烦让客服回电""催一下"。命中预约任务后用户需要**跟踪处理进度**。

**词槽**：
| key | 标签 | 类型/校验 | 必填 |
|---|---|---|---|
| phone | 联系电话 | regex | ✅ |
| order_no | 订单/工单号 | text | 条件（有单号优先） |
| action | 用户诉求 | enum [查进度, 催单, 改期, 取消] | ✅ |

**机器人问句**：
1. `亲亲，您是要查询预约进度，还是需要催促处理呢？`（action 枚举：1.查进度 2.催单 3.修改预约 4.取消预约）
2. `方便提供一下您预约时留的电话吗？`（phone）
3. `如果有工单号也可以告诉我，我帮您查得更快`（order_no，选填）
4. **查单动作**：call_api 查单接口（传 phone/order_no）→ 回显：`查到您的预约：{service_type}，状态：{status}（待上门/已派单/已完成），师傅电话 {tech_phone}`
5. 分支：
   - action=催单 → `好的，已为您催促售后尽快联系，请保持电话畅通`（调催单接口）
   - action=取消 → `好的，已为您取消预约`（调取消接口）

**触发词**：查单、催单、派单、预约查询、工单、进度、师傅什么时候来、还没联系我
**例句**：我昨天报了个单子你查查 / 之前预约的麻烦让客服回电 / 催一下 / 师傅什么时候来

**关键设计（跟踪闭环）**：这是"任务跟踪"的收口——预约类任务（任务1/2/4）完成后生成单号，用户随时可回来用本任务查状态/催办，闭环"命中任务→预约→跟踪→完成"。

### 任务 4：费用查询（服务费/换芯费/拆机费）（service_fee）

**背景**：4 个费用会话 + 换芯/移机会话里的费用追问。真实坐席按"滤芯来源+距离"算费。

**词槽**：
| key | 标签 | 类型/校验 | 必填 |
|---|---|---|---|
| fee_type | 费用类型 | enum [上门换芯, 自备滤芯换芯, 单独拆机, 二次安装, 维修检查, 首次安装] | ✅ |
| filter_source | 滤芯来源 | enum [沁园提供, 自备] | 条件(fee_type=上门换芯时) |
| distance | 距离范围 | enum [20公里内, 20公里外] | ✅ |

**机器人问句**：
1. `亲亲，您想了解哪项服务的费用呢？`（fee_type 枚举：1.上门换芯 2.自备滤芯上门 3.单独拆机 4.二次安装 5.维修检查 6.首次安装）
2. 分支 fee_type=上门换芯 → `这次用的是沁园提供的滤芯，还是您自己买的滤芯呢？`（filter_source）
3. `您的地址距离售后网点大概在20公里内还是20公里外呢？`（distance）
4. **算费动作**：按规则计算并返回结论：
   - 沁园滤芯+20公里内：`只收滤芯费用，不收取服务费`
   - 自备滤芯+20公里内：`上门更换服务费60元/台`
   - 单独拆机+20公里内：`服务费50元/台`
   - 20公里外：`超出部分按1.5元/公里加收单程远程费`
   - 首次安装：`首次安装免费（改管道/加配件/特殊开孔除外）`
   - 维修检查：`保内免费，保外按标准收取`
5. 追问 `需要为您预约上门服务吗？` → 是 → 转入任务1/2 的预约流程

**触发词**：多少钱、费用、收费、价格、服务费、拆机费、安装费、换芯费用、免费
**例句**：保修期维修要给钱吗 / 换滤芯还要加60费用 / 你们是免费上门服务吗 / 换芯收费吗

**关键设计（跟踪闭环）**：费用结果由规则引擎算（不是死 FAQ），且**费用结论后接预约入口**（"需要为您预约吗"），把"问价"转化为"下单"，闭环转化。

## 四、任务间联动（跟踪闭环总览）

```
用户触发 → 任务1/2/4（预约/报修/费用→转预约）→ 完成动作生成单号 orderId
                                                        ↓
              用户回头"查单/催单" → 任务3（order_track）按 phone/单号查状态、催办、取消
                                                        ↓
              预约上门 → 师傅完成 → 用户可再发起新需求（换芯→保养→报修）
```

**跨任务共享**：
- **电话是全局主键**：所有预约类任务第一词槽都是 phone，查档接口回填档案（姓名/地址/型号），用户多次服务免重复填写
- **单号贯穿**：完成动作统一返回 `orderId`，回显给用户（"单号 #{orderId}"），任务3 用单号跟踪
- **失败兜底**：所有 call_api 动作失败 → 转人工事件（transfer_human）+ 失败话术，用户可转人工（已有能力）

## 五、实施建议

1. **查档接口**：新增 `POST /api/mock/user/query`（开发用 mock，生产接真实 CRM），返回 `{ name, address, model, purchase_date, channel }`
2. **预约/查单/催单/取消接口**：新增 mock 接口，供 4 个任务的 call_api 步骤调用
3. **任务落库**：按现有 task 表 DSL（slots + steps）写入 4 个任务定义，配触发词/例句（已在上文给出）
4. **测试**：每个任务走完整流程（触发→收集→确认→动作→单号→查单），纳入 action-system 测试套件
5. **上线顺序**：任务1（换芯）→ 任务2（故障）→ 任务3（查单）→ 任务4（费用），前两个覆盖最高频意图

## 六、补充：低优先意图（可后续做）

- **资料/教程/人工**：多为 FAQ 即可（换芯视频/售后电话/人工入口已有或可加 FAQ），无需任务化
- **产品/活动**：回收/优惠/以旧换新 → FAQ + 商城引导，无需任务
- **查用户购买信息**（"查一下机器什么时候买的"）：可并入任务3（按 phone 查档案回显）
