# 客服对话分析 + 4 个任务流程设计方案（基于 0818.xml）

> 数据来源：`D:\沁园录音\0818.xml`（2026/8 真实坐席-客户微信对话，共 16.5 万条记录、14647 会话）
> 分析方法：抽前 100 个**有效业务会话**（客户有业务表达 + 坐席有实质回复，全文见 `docs/0818-top100-analysis.txt`）逐条分析 + 结构化统计
> 目的：抽取用户意图/词槽/坐席关键回复与反问，设计 4 个任务流程，解决"命中任务后缺乏跟踪处理"。

### 1.2 词槽（坐席实际收集的信息，按频次）

电话(60) > 号码(43) > 手机(26) > 型号(24) > 台数(23) > 地址(21) > 机器型号(15) > 上门时间(11) > 期望时间(11) > 水电是否接通(11) > 店铺(10) > 滤芯来源-自备(9) > 姓名(8) > 购买日期(8) > 购买渠道(5)

**核心发现**：
- **电话是第一词槽**（60/100 会话坐席先要电话查用户档案），且查档后**回显确认**（"15194596648 河南省/洛阳市/新安县/汉关街道鹏程家苑2-1601 UR-Q3626-纯水机 2025-08-02，您看信息对吗"）
- **型号、地址、上门时间、水电是否接通**是安装/换芯类必填
- **台数**（"两台都要换芯吗"）、**滤芯来源**（自备/沁园）影响费用计算

### 1.3 坐席结论性回复（跟踪闭环关键词，按频次）

工单(40) > 远程费(32) > 帮您预约(29) > 反馈(25) > 保外(16) > 联系您(16) > 只收滤芯费用(12) > 派单(10) > 统一保修(9) > 已预约(9) > 没有信息(7) > 预约好了(6) > 没有预约(4) > 免费安装(3) > 取消(3) > 升级/专员(2)

### 1.4 坐席反问句式（收集词槽的提问）

- 查档："亲~您还记得您下单购买机器或者预约安装机器时留的电话吗？麻烦亲提供一下这个电话，我需要查询您的用户信息"

- 安装前确认："为了确保机器安装后能够正常使用，工程师在安装时需要进行出水和通电测试。跟您确认一下，目前您安装区域的水电是否已经接通？"
- 收尾："亲亲，请问还有其他可以帮您的吗？"

## 二、现有任务的问题（为什么"命中后缺乏跟踪"）

对照 0818 真实对话，现有任务流程（meter_replace / service_appointment / remove_appointment）的关键缺陷：

1. **缺"查档回显确认"步骤**：真实坐席 60% 会话先拿电话查用户档案并回显确认（信息对不上就纠正），现有任务直接从头收集，信息容易错（真实案例：电话留错导致找不到工单）。
2. **缺"预约时间双向确认"**：真实坐席预约前确认"帮您约明天下午可以吗"，现有任务只问"期望时间"单向收集。
3. **缺"水电前置确认"**：安装类真实必问"水电是否接通"，现有任务无此词槽。
4. **缺"工单号跟踪"**：真实坐席完成预约后用户能查工单/催单/取消（工单出现 40 次），现有任务完成即结束，无查单/催单/改期/取消能力。
5. **故障类无"自助排查→升级预约"分层**：真实坐席先给自助方案（拔电重启/复位/看灯），解决不了才预约；现有无故障任务，且"一上来就预约上门"会造成无效上门。
6. **费用未结构化**：换芯费按"滤芯来源+距离"、安装费按"保内/保外+远程费+配件费"规则算，现有无费用任务，全靠 FAQ 死话术。

## 三、4 个任务流程设计方案

### 任务 1：预约上门换芯（filter_replace）

**意图**：用户要师傅上门换滤芯。**触发词**：换芯、换滤芯、上门换滤芯、滤芯到期、更换滤芯、滤芯提醒。

**词槽**（按收集顺序）：
| key | 标签 | 类型/校验 | 必填 |
|---|---|---|---|
| phone | 联系电话 | regex `1[3-9]\d{9}` | ✅（第一槽，查档用） |
| machine_model | 机器型号 | text | ✅（查档回填） |
| customer_name | 姓名 | text | ✅（查档回填） |
| address | 服务地址 | length≥5 | ✅（查档回填） |
| filter_source | 滤芯来源 | enum [沁园滤芯, 自备滤芯] | ✅（费用分支） |
| unit_count | 换芯台数 | number≥1 | ✅（"两台都要换芯吗"场景） |
| time_slot | 期望上门时间 | text | ✅ |

**机器人问句**：
1. `亲~您还记得购机或预约安装时留的电话吗？麻烦提供一下，我需要查询您的用户信息`（phone）
2. **查档动作**（call_api 查档接口）→ 回显：`查到您的信息：{姓名}，{地址}，{型号}（{购买日期}），对吗？` → 已填槽自动回填 → 用户确认/纠正
3. `这次换芯，您用的是沁园提供的滤芯，还是自己买的呢？`（filter_source）
4. `需要换几台机器呢？`（unit_count）
5. `您期望师傅什么时间上门？比如上午/下午`（time_slot）
6. **预约时间双向确认**：`帮您预约 {time_slot} 上门可以吗？`（确认/否认）
7. 确认清单 → 提交

**完成动作**：call_api 预约换芯接口 → done_message：`已为您预约上门换芯（工单号 #{orderId}），售后24小时内联系您，请保持电话畅通`
**分支**：filter_source=自备 → 追加 `温馨提示：自备滤芯上门更换20公里内服务费60元/台，超20公里按1.5元/公里加收单程远程费`

**例句**：预约换芯 / 需更换滤芯 / 上门换滤芯 / 滤芯到期了 / 换一个滤芯

---

### 任务 2：预约安装（install_appointment）

**意图**：用户要预约净水机安装。**触发词**：安装、预约安装、装机、装净水器、首次安装。

**词槽**：
| key | 标签 | 类型/校验 | 必填 |
|---|---|---|---|
| phone | 联系电话 | regex | ✅ |
| machine_model | 机器型号 | text | ✅（查档回填） |
| customer_name | 姓名 | text | ✅（查档回填） |
| address | 安装地址 | length≥5 | ✅（查档回填） |
| purchase_channel | 购买渠道 | enum [线上, 线下] | ✅ |
| purchase_date | 购买日期 | text | ✅（查档回填） |
| water_electric | 水电是否接通 | enum [已接通, 未接通] | ✅（真实必问） |
| time_slot | 期望上门时间 | text | ✅ |

**机器人问句**：
1. `亲~您预约安装时留的电话是多少呢？我帮您查询用户信息`（phone）
2. **查档回显**（同上）
3. `为了确保安装后正常使用，师傅需要做出水和通电测试。跟您确认一下，目前安装区域的水电是否已经接通？`（water_electric）——**未接通 → 提示**：`好的，建议水电接通后再预约安装哦，需要的话我可以帮您记下需求`（分支，不强行约）
4. `您期望什么时候上门安装？`（time_slot）
5. **双向确认**：`帮您预约 {time_slot} 上门安装可以吗？`
6. 确认 → 提交

**完成动作**：call_api 预约安装 → done_message：`已为您预约安装（工单号 #{orderId}），售后会提前联系您确认上门时间`
**分支**：water_electric=未接通 → 完成话术追加 `温馨提示：首次安装免费（改管道/加配件/特殊开孔除外），请在水电接通后联系我们重新预约`

**例句**：预约安装 / 我要装净水机 / 帮我安排安装 / 买的新机器需要上门装

### 任务 3：故障报修与自助排查（fault_repair）

**意图**：机器故障（响/红灯/不出水/漏水/报错）。**触发词**：坏了、故障、红灯、不出水、漏水、滴水、异常、响、E9、报错、复位。

**词槽**：
| key | 标签 | 类型/校验 | 必填 |
|---|---|---|---|
| fault_type | 故障类型 | enum [异响, 指示灯异常, 不出水, 漏水/滴水, 报错代码, 其他] | ✅ |
| machine_model | 机器型号 | text | ✅ |
| error_code | 报错代码 | text（fault_type=报错代码时） | 条件 |
| symptom | 具体现象 | text | ✅ |
| tried_steps | 已尝试操作 | enum [未尝试, 拔电重启, 复位, 已尝试均无效] | ✅ |
| phone | 联系电话 | regex | ✅（升级预约时） |
| address | 服务地址 | length≥5 | ✅（升级预约时） |
| time_slot | 上门时间 | text | ✅（升级预约时） |

**机器人问句（自助排查→升级预约分层）**：
1. `亲亲，您的机器出了什么问题呢？`（fault_type 枚举）
2. 分支=报错代码 → `方便告诉我屏幕上的报错代码吗？比如 E1、E9`（error_code）
3. `请问您的机器型号是？`（machine_model）
4. **自助排查引导**（分支关键）：
   - 异响/不出水 → `亲亲，您可以先试试：拔掉电源插头等待十五分钟再插上，看是否恢复；如果是滤芯到期，按选择键选到对应滤芯、长按复位键6秒复位。您试过这些了吗？`（tried_steps）
   - 已尝试无效 → `好的，那我为您预约师傅上门检查` → 转入预约（收 phone/address/time_slot）
   - 未尝试 → 提示先试，**不直接约上门**（避免无效上门）
5. 确认 → 提交

**完成动作**：call_api 报修预约 → done_message：`已为您登记故障报修（工单号 #{orderId}），售后工程师24小时内联系您；期间自助排查成功可回复"取消"撤销预约`

**例句**：放一壶水主机响一个小时 / 水龙头间歇性滴水 / 换滤芯后还是红色 / E9代表什么 / 机器不出水了

### 任务 4：工单查询/催单/改期/取消（order_track）

**意图**：预约后跟踪处理（"怎么没人联系我""催一下""电话留错了咋办"）。**触发词**：查单、催单、工单、单号、进度、没人联系、没联系、改期、取消预约。

**词槽**：
| key | 标签 | 类型/校验 | 必填 |
|---|---|---|---|
| phone | 联系电话 | regex | ✅ |
| order_no | 工单号 | text | 条件（有则优先） |
| action | 用户诉求 | enum [查进度, 催单, 改期, 取消] | ✅ |
| new_time | 新期望时间 | text（action=改期时） | 条件 |

**机器人问句**：
1. `亲亲，您是要查询工单进度、催促处理、修改时间，还是取消预约呢？`（action 枚举）
2. `方便提供一下您预约时留的电话吗？`（phone，有工单号可直说）
3. `工单号也可以告诉我，查得更快`（order_no 选填）
4. **查单动作**：call_api 查单 → 回显：`查到您的工单：{service_type}，状态：{status}（待上门/已派单/已完成），师傅电话 {tech_phone}`
5. 分支：
   - 催单 → `好的，已为您催促售后尽快联系，请保持电话畅通`（催单接口）
   - 改期 → `请问您希望改到什么时间？`（new_time）→ `好的，已为您改期到 {new_time}，师傅会提前联系您确认`
   - 取消 → `好的，已为您取消预约（工单号 #{orderNo}）`（取消接口，**提示可重新预约**——真实案例"取消后改不了"）

**触发词**：查单、催单、工单、进度、没人联系、没联系我、改期、取消预约、什么时候来
**例句**：我预约安装怎么没人联系我 / 催一下 / 我电话留错了咋办 / 工单进度

## 四、任务间联动（跟踪闭环总览）

```
用户触发 → 任务1/2/3（换芯/安装/报修）→ 完成动作生成工单号 orderId
                                                  ↓
        用户回头查进度/催单/改期/取消 → 任务4（order_track）按 phone/单号处理
                                                  ↓
              师傅上门完成 → 用户可发起新需求（换芯→保养→报修→费用）
```

**跨任务共享**：
- **电话是全局主键**：4 个任务第一词槽都是 phone；查档接口回填档案（姓名/地址/型号/购买日期/渠道），多次服务免重复填写（真实坐席做法）
- **工单号贯穿**：任务 1/2/3 完成动作统一返回 orderId 回显，任务 4 用 phone/orderNo 跟踪
- **费用规则统一**：滤芯来源+距离算费（换芯）、保内/保外+远程费+配件费（报修）、首次免费（安装）——规则引擎实现，4 个任务可复用
- **失败兜底**：所有 call_api 失败 → transfer_human 事件 + 失败话术（已有能力）

## 五、实施建议

1. **查档接口**：`POST /api/mock/user/query`（mock，生产接 CRM），入参 phone，返回 `{ name, address, model, purchase_date, channel }`；查无记录回 `{ found: false }` → 机器人改问"还有其他号码吗"（真实话术）
2. **预约/查单/催单/改期/取消接口**：新增 mock 接口供 call_api 步骤使用
3. **任务落库**：按 task 表 DSL（slots + steps）写入 4 个任务，配触发词/例句（上文已给）
4. **测试**：每任务完整流程（触发→收集→查档→双向确认→动作→工单号→任务4查单），纳入 action-system 套件
5. **上线顺序**：任务1（换芯）→ 任务2（安装）→ 任务3（故障）→ 任务4（查单）——前三覆盖最高频意图，任务4 收口跟踪

## 六、低优先项（FAQ 可覆盖，暂不任务化）

- **人工/电话**（7 会话）："人工客服""人工电话多少" → 已有 human_agent FAQ + 转人工
- **绑定/扫码/小程序操作**（6 会话）：绑定教程/条码输入 → FAQ + 图文指引
- **复位/换芯操作指导**（2 会话）：可并入任务3 的自助排查分支
- **活动/商城/以旧换新**（2 会话）：FAQ + 商城链接引导
