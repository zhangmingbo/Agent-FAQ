# LLM 驱动任务对话引擎 — 详细设计方案

> 版本：v1.0（评审稿）
> 背景：现有任务引擎是"表单式"对话（状态机按序问槽位 + LLM 只做字段提取），用户真实话术（纠正/插话/乱序/自由表达）不断打破表单，补丁式修复反复翻车。本方案将**对话主导权交给 LLM**（agentic dialogue），系统只保留校验、确认、执行与降级护栏。

---

## 1. 目标与原则

| 目标 | 说明 |
|---|---|
| 真人级任务对话 | 用户纠正、插话、乱序、口语化表达天然正确 |
| 运营可配置 | 话术/风格/规则全部走提示词注册表（管理后台），不写死在代码 |
| 安全护栏 | LLM 填的值必须过业务校验；任务完成必须用户确认 |
| 可降级 | LLM 不可用时回退现有表单模式，客服不宕机 |

**核心原则：LLM 负责"说什么"，系统负责"能不能"（校验/确认/执行）。**

---

## 2. 每轮对话协议（LLM 输入 → 输出）

### 2.1 LLM 输入（System + User）

**System（运营可配置，注册表键 `dialogue.system`）**：

```
你是{品牌}售后客服，正在帮用户办理「{任务名}」。
需要收集以下信息（名称、必填、格式约束）：
{字段清单}
对话要求：
- 回复亲和、简洁、口语化
- 用户纠正/插话/提问时，先响应用户当前意图
- 所有信息收集齐后，请用户确认；只有用户明确确认后才视为完成
- 不要编造用户没提供的信息
```

**User（系统每轮构造，注册表键 `dialogue.user`）**：

```
【任务】{任务名}
【需要收集】{字段: 标签(必填,格式/枚举)}
【已收集】{key=value, ...}（无则"无"）
【对话历史】（最近 {N} 轮）
  用户: ...
  客服: ...
【最新输入】{用户这句话}
请输出 JSON：
{
  "slots": { "字段key": "新值", ... },   // 本次更新/新增的槽位；无则 {}
  "reply": "回复用户的话",
  "ask_confirm": true | false,           // 信息已齐、需要用户确认时 true
  "question": "用户输入的提问原文" | null // 用户这句话是在提问时填原文
}
```

### 2.2 LLM 输出 → 系统处理流程

```
LLM 输出 JSON
  ↓
① 解析 JSON（失败 → 重试 1 次 → 降级）
  ↓
② 校验 slots 每个值（phone 格式 / 枚举成员 / 长度等业务规则）
     不合格 → 丢弃该值，回复用系统重问话术（或 LLM reply）
  ↓
③ 写入槽位 → 持久化 → 追加对话历史
  ↓
④ 完整性检查：
     必填未齐 → 正常回复（LLM reply）
     必填已齐 → 进入确认态：回复确认清单（确认清单由系统生成或 LLM 生成）
  ↓
⑤ ask_confirm=true 且用户明确确认（确认词判定）→ 执行动作（写库/调API）→ 完成
     ⚠️ 门禁：LLM 输出 completed/ask_confirm 只是"建议"，必须叠加用户确认判定
```

## 3. 状态机退化后的角色

原状态机（collecting → confirming → done/cancelled）**保留状态概念，但不再做对话编排**：

| 状态 | 现在的作用 |
|---|---|
| collecting | 信息未齐的检查器（必填字段是否都有值） |
| confirming | 信息已齐、等待用户确认 |
| done / cancelled | 终态（动作已执行 / 用户取消） |

- 删掉：步骤链（collect 顺序）、逐槽位提取循环、锚点探测、纠正/修改正则
- 保留：取消意图、确认门禁、会话超时清理、store 持久化

---

## 4. 护栏设计（必须项）

| 护栏 | 实现 | 已有/新增 |
|---|---|---|
| 业务校验 | LLM 槽位值过 `validateSlot`（phone/枚举/长度），不合格丢弃+重问 | 已有，保留 |
| 确认门禁 | `ask_confirm` 只是建议；动作执行必须叠加 `dialogueRules.isConfirm` 或 LLM 判定确认 | 已有规则，保留 |
| 防编造 | System 提示词明确"不要编造用户没提供的信息"；校验兜底 | 新增（提示词） |
| 解析失败 | JSON 解析失败 → 重试 1 次 → 降级表单模式 | 新增 |
| 降级通道 | LLM 不可用/超时/未配置 → 自动切回现有表单模式（dialogManager 旧逻辑保留） | 新增（模式开关） |
| 上下文窗口 | 对话历史取最近 10 轮，避免 token 膨胀 | 新增 |
| 取消 | 用户表达取消 → cancelled，清理会话 | 已有 |

## 5. 提示词注册表新增（运营可配置）

| 键 | 用途 |
|---|---|
| `dialogue.system` | 角色 + 任务规则 + 对话风格 |
| `dialogue.user` | 每轮用户消息模板（占位符：taskName/slotDesc/filledDesc/history/text） |
| `dialogue.confirm` | 确认清单话术模板 |
| `dialogue.completed` | 完成话术模板（叠加动作返回） |

管理后台「LLM 智能层」自动出现这些调用点，运营直接编辑，保存即生效。

## 6. 与现有代码的映射

| 文件 | 改动 |
|---|---|
| `services/taskflow/dialogManager.js` | 重写为 `LLMDialogManager`（每轮调 LLM 决策）；**旧逻辑保留为 `RuleDialogManager`（降级模式）** |
| `services/taskflow/nlu.js` | 新增 `dialogue()`：构造提示词 + 调 LLM + 解析/校验输出 |
| `services/taskflow/llm.js` | 新增 `dialogueTurn()`（chat 封装，JSON 输出模式） |
| `services/llmPrompts.js` | 新增 `dialogue.*` 提示词定义 |
| `services/taskflow/stateMachine.js` | 状态枚举保留，删除步骤转移表 |
| `services/taskflow/index.js` | `processInput` 契约不变；按模式分发：`llm` → LLMDialogManager，`rule` → RuleDialogManager |
| `validator.js / actionRegistry.js / store.js / taskDefs.js` | 不变 |
| `faq-engine.js / routes/chat.js` | 不变（集成点契约保持） |

**对话模式开关**：复用现有 `nlu_mode`（`llm` = LLM 对话，`hybrid` = LLM 对话优先规则降级，`rule` = 纯表单模式）。

## 7. 评测方案（用 tt.xml 真实对话）

**目标：不再"测着感觉"，用真实数据量化。**

1. **建黄金评测集**：从 tt.xml 的 28 个会话中，提取"信息收集型"流程（如预约登记、查档核对），标注：触发句 / 每轮正确槽位值 / 最终完成。
2. **评测脚本** `tests/dialogue.eval.mjs`：
   - 逐会话回放：把"用户话术"按轮喂给引擎
   - 断言：每轮槽位更新正确率、流程完成率、多轮无卡死（不超过 N 轮）
3. **回归**：现有 `taskflow.test.mjs`（规则模式 49 用例）保留，作为降级路径的回归保障。
4. **报告**：输出准确率/完成率/平均轮数，作为每次改动的对比基线。

## 8. 实施阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| 一 | 对话协议定稿 + `LLMDialogManager` 骨架 + `dialogue()` 接入（先用 mock LLM 输出可测） | 黄金用例能跑通（mock） |
| 二 | 真实 LLM 接入 + 护栏（校验/确认门禁/解析重试/降级开关） | 预约/换表任务真实对话跑通 |
| 三 | 评测集 + 提示词打磨（用 tt.xml 用例迭代 `dialogue.*`） | 评测集完成率 ≥ 90% |
| 四 | 管理后台「对话引擎」配置（模式切换、话术编辑） | 运营可自助切换与调优 |

---

## 9. 风险与成本

| 项 | 评估 |
|---|---|
| 延迟 | 每轮 1 次 LLM（1~2s），比现状最坏 3 次更稳 |
| 成本 | 每轮 1 次调用；DeepSeek 单价低，客服场景可接受 |
| LLM 乱填/乱完成 | 校验 + 确认门禁兜底 |
| 输出不稳定 | JSON 重试 + 降级表单模式 |
| 评测投入 | 需从 tt.xml 标注黄金用例（一次性投入，之后持续受益） |

---

## 10. 验收标准（一句话）

> 用户按真实数据里的说法（"安排个上门换滤芯"、"地址不对，地址是嘉定江桥"、"我姓五不对是吴"、"下午3点"）与机器人对话，**纠正/插话/乱序天然正确，信息齐后确认、确认后写库**；LLM 故障时自动降级表单模式，客服不断线。
